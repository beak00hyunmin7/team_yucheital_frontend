# 유체이탈 프론트엔드

## 실행 방법

**준비물**: Python 3.10 이상 (설치할 때 "Add python.exe to PATH" 체크)

```powershell
git clone https://github.com/beak00hyunmin7/team_yucheital_frontend.git
```

1. `project_yucheital/run_test_server.bat` 더블클릭
2. 브라우저가 `http://127.0.0.1:8000/vtkjs.html` 로 열리고, 오른쪽 위가 🟢 이면 성공
3. 끌 때는 검은 창에서 `Ctrl+C`

- 이건 **테스트용 가짜 서버**(`project_yucheital/dev_server/mock_server.py`)라서 예측 그림은 진짜 AI 결과가 아닙니다. 화면 기능 확인용입니다.
- **진짜 AI 서버**를 쓰려면 서버 저장소([team_yucheital_backend](https://github.com/beak00hyunmin7/team_yucheital_backend))의 `prediction_server/run_windows.bat` 을 실행하고(체크포인트 `best.pt` 필요), 테스트 서버는 끈 채로 `yuche_frontend/vtkjs.html` 을 열면 됩니다. (서버 이전 PR 이 병합되기 전에는 AI 저장소의 `terrainFlowSim/webapp/run_windows.bat`)
- 서버 주소 기본값: `http://호스트:8080` 으로 열면 같은 호스트의 8000번 포트, 그 밖의 http(s) 주소(공개 링크·테스트 서버처럼 화면과 `/api` 를 한 주소에서 내줄 때)는 이 화면과 같은 주소, 파일을 더블클릭해 열면 `127.0.0.1:8000`. 다른 주소는 주소 뒤에 `?api=http://IP:포트` 를 붙입니다.

### 다른 PC·폰에서 쓰기 (같은 공유기)

서버 PC 에서 AI 서버(8000, `run_windows.bat` 이 `0.0.0.0` 으로 엶)와 화면을 같이 열어 줍니다.

```powershell
python project_yucheital\dev_server\static_server.py 8080 0.0.0.0
```

`python -m http.server` 로도 열리지만, 캐시 헤더가 없어 브라우저가 예전 `style.css` 를 계속 쓰는 일이 생깁니다
(화면을 고쳤는데 새 손잡이·스타일이 안 보임). `static_server.py` 는 `Cache-Control: no-cache` 를 붙여 매번 바뀌었는지 확인하게 합니다.
`style.css` 를 고치면 `vtkjs.html` 의 `style.css?v=` 값도 올려 주세요.

다른 기기에서는 `http://서버PC의IP:8080/vtkjs.html` 만 열면 됩니다 (API 주소는 자동으로 `서버PC의IP:8000`).
서버 PC 의 IP 는 `ipconfig` 의 IPv4 주소입니다. 접속이 안 되면 Windows 방화벽에서 8000·8080 포트(또는 python.exe)의 인바운드 허용을 확인하세요.
HTTP 평문이라 같은 네트워크에서 로그인 비밀번호가 보일 수 있으니, 공용 Wi-Fi 에서는 쓰지 마세요.

## 화면 구성 (지도 우선)

지도가 화면을 채우고, 나머지는 그 위에 떠 있는 패널입니다 (`yuche_frontend/vtkjs.html` + `style.css`).
시안(목업)의 수치·색을 그대로 따릅니다: 다크 `#0d1218` 바탕, 포인트색 `#4cc3ff`(그 위 글자는 `#06202e`), 패널 폭 340px, 레일 64px, Noto Sans KR.

| 영역 | 내용 |
|---|---|
| 첫 화면(로고) | 접속하면 프로젝트 로고를 약 2초 보여 준 뒤 본 화면으로 넘어감(누르면 바로). **`yuche_frontend/logo.png` 를 넣으면 그 그림**이, 없으면 기본 물방울 그림이 나옴 |
| 왼쪽 레일 | 로고 · 예측 · 기록(건수 배지) / 아래쪽에 서버 상태 점 · 테마 · 🎄 · 계정(누르면 로그인·가입 또는 이메일·로그아웃 메뉴). 상단바와 안내 배너는 없음 |
| 지도 | 예측 결과를 화면 전체에 꽉 채워(cover) 표시하고 왼쪽·아래를 어둡게 깔아 패널을 살림. 정사각 지도라 긴 변 쪽이 잘리는데, 배수구 후보가 잘리는 쪽에 있으면 보이는 창을 그쪽으로 옮김. `전체 보기` 버튼으로 잘림 없이 볼 수도 있음. **마우스 드래그로 이동, 휠·`+`/`−` 버튼·핀치·더블클릭(2.5배 ↔ 원래)으로 확대·축소**(50%~800%, 커서 아래 점 기준). 가장자리가 화면 안으로 끌려 들어와 빈 공간이 생기지 않고, 확대해도 배수구 표시는 같은 크기로 같은 지점에 붙음. 새 결과를 받으면 처음 상태로. 배수구 후보는 그림에 굽지 않고 빨간 원(비율 좌표)과 라벨 카드로 얹음. 데이터 모드는 등고선(m)·음영기복이 있는 지도, 이미지 모드는 오버레이 |
| 왼쪽 조건 패널 | 입력 방식 · 파일 · 강우량(슬라이더 + 30/50/80 빠른 선택) · 경과 시간 · 고급 설정(이미지 색 체계, 격자 크기) · 실행. 경과 시간은 0초(강우 시작 직후)에서 시작. 접으면 한 줄 알약(`50mm · 0초`) |
| 오른쪽 위 칩 | 최대 침수(cm) · 5cm 이상 면적(%) = 서버 `stats`. `결과 이미지`(입력 등고선·예측·오버레이·분석 지도 모아보기), `기록` 서랍(최근 6건, 누르면 그 결과를 지도에 엶) |
| 아래 시간 슬라이더 | 시점별 예측(18~120초 6장 + **예측할 때 입력한 시점**)을 이어 재생. 처음부터 입력한 시간을 가리키고, 받는 동안에는 `시점별 예측 중 3 / 7` 과 진행 막대를 크게 보여 줌. 재생·슬라이더를 만지면 `지도` → `시간 변화` 보기로 바뀜 |
| 패널 옮기기 | 조건 패널(제목 줄)·기록 서랍(제목 줄)·요약 칩과 시간 슬라이더(왼쪽 점 6개 손잡이)를 끌어 원하는 자리에 둘 수 있음. 접힌 '조건' 알약도 끌 수 있음. 위치는 브라우저에 저장되고 화면 밖·레일 밑으로는 못 나감. 손잡이 더블클릭 = 그 패널만, 레일의 초기화 버튼 = 전부 원래 자리. 모바일(세로 쌓기)에서는 끌 수 없음 |
| 3D 지형 보기 | 시간 슬라이더 위 `지도 / 시간 변화 / 3D` 중 `3D`. 서버가 `grid3d`(96×96 높이·수심)를 주면 나타남. 높이대로 세운 지형 위에 수심만큼 물 면을 얹고, 물이 있는 곳에서 입자가 내리막을 따라 흐름(지형 경사 기반 시각 효과, 유속 예측 아님). 시간 슬라이더·재생과 연동, 배수구 후보는 빨간 핀. 드래그 회전 · 휠 확대 · Shift/오른쪽 드래그 이동 · 더블클릭 초기화, 오른쪽 아래 도구에서 높이 과장·물 흐름 켜고 끄기. three.js 는 3D 를 처음 열 때 CDN 에서 받음(오프라인이면 2D 로 돌아감). 저장된 기록에는 높이 자료가 없어 3D 버튼이 안 보임 |
| 패널 크기 조절 | 조건 패널(오른쪽·아래·오른쪽 아래 모서리), 기록 서랍(왼쪽·아래·왼쪽 아래 모서리), 시간 슬라이더(양옆)의 가장자리를 끌어 크기 변경. 끄는 쪽 반대편 가장자리는 그대로 있음. 크기도 위치와 함께 저장(`yuche_layout_v1`의 `size:키`)되고 화면보다 커지지 않음. 가장자리 더블클릭 = 그 패널 크기만, 레일의 초기화 버튼 = 위치·크기 전부 원래대로. 모바일에서는 기본 크기 |
| 빈 화면 · 파일 놓기 | 처음 화면에 순서 안내와 `파일 고르기` / `샘플 지형으로 해보기`(서버에 샘플이 있을 때). 파일은 화면 아무 곳에나 끌어다 놓아도 되고, 확장자에 맞는 입력 방식으로 자동 전환. 예측 중에는 지도 가운데에 표시 |
| 입력 확인 창 | 학습 형식이 아닌 색 체계(회색조·무지개 등)라 서버가 높이로 읽어 변환했을 때: 원본 / 읽은 결과 / 예측 미리보기와 "높은 곳을 맞게 읽었나요?"(맞아요·반대예요, 색 체계 직접 선택). 바꾸면 그 자리에서 다시 예측 |
| 오류 안내 창 | 지형도·스캔 도면처럼 색이 높이가 아닌 이미지(서버 422 + `code: "unreadable_image"`): 이유와 다음 행동(DEM 올리기 · 높이를 색으로 칠한 이미지 · 샘플로 해보기) |

- 1000px 이하(모바일)에서는 지도 → 칩 → 시간 슬라이더 → 조건 패널 → 기록 순으로 세로로 쌓입니다.
- 분석 기록 화면(표)·로그인·테마·크리스마스 모드는 그대로입니다.

### 서버가 주는 값 (`POST /api/predict`)

기존 필드에 더해 이 화면이 쓰는 것들입니다. 없어도(구버전 서버·테스트 서버) 화면은 그 부분만 숨기고 동작합니다.

| 요청 필드 | 설명 |
|---|---|
| `color_scheme` | 이미지 모드. `auto`(기본) 또는 `/api/color-schemes` 의 key |
| `reverse` | 이미지 모드. `true` 면 높낮이를 반대로 해석 |

| 응답 필드 | 설명 |
|---|---|
| `stats` | `{ max_depth_cm, wet_area_pct, wet_threshold_cm }` 지도 위 칩 |
| `map_jpg_base64` | 데이터 모드의 깨끗한 지도(JPEG). 없으면 오버레이로 대체 |
| `color_info` | 이미지 모드. `{ scheme, label, auto, reversed, converted, legend, warnings }` — `converted` 면 입력 확인 창을 띄움 |
| `original_png_base64` | 서버가 색 체계를 변환했을 때 올린 원본 |
| `grid3d` | 3D 보기용 `{ n, height_u16, depth_u16, depth_unit_m, max_depth_m, relief_m, extent_m }`. 높이(0..1×65535)·수심(m/`depth_unit_m`)을 uint16 리틀엔디언 base64 로, 0행 = 그림 위쪽. 없으면 3D 버튼을 숨김 |
| 오류 422 + `code` | `unreadable_image` → 오류 안내 창. 그 밖의 422 는 기존처럼 알림 |

테스트 서버(`mock_server.py`)도 같은 필드를 흉내 냅니다. 파일명에 `topo` 가 들어가면 `unreadable_image` 오류를, 회색조 이미지는 변환 + 입력 확인을 시험할 수 있습니다.

## 분석 기록 저장

분석 기록은 AI 서버의 `/api/history` 에 저장됩니다(MySQL + 썸네일 파일). 로그인한 사용자 본인 기록만 보이고, 다른 PC·브라우저에서도 같은 기록이 보입니다. 목록은 최신순 최대 50건입니다.

| 동작 | API |
|---|---|
| 목록 | `GET /api/history` |
| 저장 (예측 완료 시 자동) | `POST /api/history` |
| 이름 변경 | `PATCH /api/history/{id}` (`{ name }`) |
| 삭제 / 전체 삭제 | `DELETE /api/history/{id}` / `DELETE /api/history` |

- 모든 요청에 `Authorization: Bearer 토큰` 헤더가 필요합니다. 토큰은 `/api/auth/login` 에서 받아 `localStorage['yuche_token']` 에 저장합니다.
- 비로그인 상태나 DB 가 끊긴 상태에서는 기록이 저장되지 않습니다. 저장에 실패하면 결과 안내에 한 줄로 표시됩니다.
- 예전 localStorage 기록(`yuche_history_{이메일}`)은 서버로 옮기지 않았고, 화면에도 보이지 않습니다.
- 테스트 서버도 같은 API 를 제공하지만 기록을 메모리에만 두므로 서버를 끄면 사라집니다.
- 기록의 그림(`thumbnail`)은 예측 화면에서 본 것과 같은 해상도(긴 변 최대 1024px, JPEG)로 저장합니다. 배수구 원은 그림에 굽지 않고, 기록을 다시 열 때 `drain` 좌표로 얹습니다. (예전 기록은 360px 로 저장돼 있어 다시 열면 흐립니다)

## 배수구 후보 위치

`POST /api/predict` 응답의 `drain_candidate.image` `{ x, y }` 는 그림 왼쪽 위 기준 0~1 비율입니다. 예측 배수맵과 오버레이 위에 빨간 원으로 표시하고, 기록의 `drain` 에도 이 값을 저장합니다.
